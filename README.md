# مساعد تسجيل الدخول — محلي أو على VPS

أداة تفتح صفحة تسجيل الدخول داخل Chrome يتحكم فيه Playwright. بعد نجاح الدخول تحفظ نسخة VPS Cookies الجلسة في Docker Volume، ولذلك تحاول فتح `personal.aspx` مباشرة بعد إعادة التشغيل أو النشر. إذا انتهت الجلسة من جهة موقع الجامعة ترجع الأداة تلقائيًا إلى صفحة الدخول والكابتشا.

يمكن تشغيلها محليًا على Windows، أو نشرها على VPS Linux عبر Coolify. في وضع VPS يعمل Chromium وPOST على السيرفر، ويظهر المتصفح داخل الداشبورد عن طريق noVNC.

الأداة لا تتجاوز Captcha ولا ترسل طلبات متوازية. عند رسالة ضغط واضحة تنتظر مدة متدرجة ثم تجهز صفحة وCaptcha جديدتين، لكن إرسال كل POST يظل بضغط المستخدم.

## نشر نسخة VPS

الطريقة الموصى بها هي Coolify باستخدام `docker-compose.yml`. لا تحتاج سيرفرين؛ Coolify والتطبيق يعملان على نفس VPS. راجع [دليل النشر الكامل](DEPLOY-COOLIFY.md).

حاوية VPS تشغّل داخليًا Node.js وChromium وXvfb وnoVNC وNginx. المنفذ العام الوحيد هو `3000` من خلال Proxy الخاص بـCoolify، أما منافذ VNC والمتصفح فتبقى داخل الحاوية.

## التشغيل السريع على Windows

1. اضغط مرتين على `start.bat`.
2. ستفتح لوحة التحكم المحلية على `http://127.0.0.1:4317`.
3. اضغط **تجهيز جلسة**. ستفتح نافذة Chrome مخصصة وتحمّل `Signin.aspx` مباشرة.
4. اكتب رقم الخريج والرقم القومي والكود التأكيدي في لوحة التحكم.
5. اضغط **إرسال محاولة واحدة** واترك نافذتي البرنامج وChrome مفتوحتين.
6. عند النجاح ستبقى نافذة Chrome على الصفحة التالية بنفس الجلسة.
7. لإيقاف البرنامج اضغط `Ctrl+C` في النافذة السوداء.

إذا لم تفتح لوحة التحكم تلقائيًا، افتح يدويًا:

```text
http://127.0.0.1:4317
```

## التشغيل من PowerShell

```powershell
npm install
npm start
```

يتطلب Node.js 20 أو أحدث وGoogle Chrome. إذا لم يوجد Chrome يحاول البرنامج استخدام Microsoft Edge تلقائيًا.

## طريقة إعادة المحاولة

- يوجد POST واحد فقط في أي لحظة.
- المهلة الافتراضية 400 ثانية (6 دقائق و40 ثانية).
- انتهاء مهلة لوحة التحكم لا يلغي POST داخل Chrome.
- لا يمكن إرسال POST آخر طالما الطلب الأول ما زال Pending.
- عند Runtime Error أو رسالة «حاول الاتصال لاحقًا» تبدأ فترة انتظار 30–120 ثانية، ثم تُجهز Captcha جديدة فقط؛ لا يُرسل POST تلقائيًا.
- عند نتيجة غير مؤكدة استخدم زر **فحص الجلسة**.
- الداشبورد يعرض ويعدّ تنقلات صفحات `.aspx` فقط، ويتجاهل CSS والصور والكابتشا وملفات WebResource.
- بطاقة **آخر طلب POST** توضح هل محاولة الدخول نجحت أو فشلت فعليًا مع HTTP والمدة؛ HTTP 200 مع رسالة «حاول لاحقًا» يُعرض كفشل دخول.
- عمل Refresh يصفر سجل الأحداث والعدادات التاريخية، لكنه يظل يعرض أي طلب حقيقي ما زال جاريًا.

## إعدادات اختيارية

يمكن ضبط الإعدادات قبل `npm start`:

```powershell
$env:REQUEST_TIMEOUT_MS="400000"
$env:MIN_POST_INTERVAL_MS="30000"
$env:BROWSER_CHANNEL="chrome"
npm start
```

- `REQUEST_TIMEOUT_MS`: مهلة المتابعة بالمللي ثانية، بين 30 ثانية و10 دقائق.
- `MIN_POST_INTERVAL_MS`: أقل فاصل بين محاولتي POST، والحد الأدنى 10 ثوانٍ.
- `BROWSER_CHANNEL`: استخدم `chrome` أو `msedge`.
- `PORT`: منفذ لوحة التحكم المحلية، والافتراضي `4317`.
- `SESSION_STATE_PATH`: مسار اختياري لحفظ Cookies الجلسة بين مرات التشغيل. نسخة Docker تضبطه تلقائيًا على `/data/session-state.json`.

## الخصوصية

- لا تضع بياناتك في `.env` أو داخل الكود.
- الأداة لا تسجل Body طلب الدخول أو القيم المدخلة.
- خيار **تذكّر رقم الخريج والرقم القومي** اختياري وغير مفعّل افتراضيًا. عند تفعيله تُحفظ القيمتان في Local Storage بشكل غير مشفر؛ الكابتشا لا تُحفظ مطلقًا.
- في نسخة VPS تُحفظ Cookies الجلسة كملف صلاحياته `0600` داخل Docker Volume دائم. الملف حساس ولا يجب نسخه أو نشره.
- زر **جلسة جديدة** أو **مسح الحقول والجلسة** يمسح ملف الجلسة المحفوظة. وقد ينهي موقع الجامعة الجلسة من جانبه في أي وقت.
- سجل التشغيل يحتفظ بآخر 50 حدثًا في الذاكرة ويعرض آخر 30 حدثًا تلقائيًا. عمل Refresh للداشبورد يمسح الأحداث القديمة ويبدأ سجلًا جديدًا، بدون إغلاق Chrome أو مسح جلسة الموقع.
- السجل لا يحتوي رقم الخريج أو الرقم القومي أو قيمة Captcha.
- الموقع الخارجي يستخدم HTTP، لذلك لا تستخدم شبكة عامة ولا تشارك Network exports دون إخفاء الرقم القومي والCookie.
- نسخة VPS محمية بـHTTP Basic Auth داخل Nginx، ويجب وضعها خلف HTTPS من Coolify واستخدام كلمة مرور قوية.
- لا تضع Token خاصًا بـBrowserless أو أي Secret داخل Git؛ نسخة VPS الحالية لا تحتاج Browserless.
